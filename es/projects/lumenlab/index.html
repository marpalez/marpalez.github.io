¿Qué es LumenLab?

LumenLab es una aplicación de escritorio para tomas de notas para laboratorios y planificación de servicios.

Programa realizado tanto desde el punto de vista de técnico de laboratorio como de project manager, para que ambos puedan utilizarlo de manera intuitiva.

Se pueden implementar normas, toma de notas y equipo utilizados. También se pueden personalizar los diferentes estados de los proyectos, los técnicos y más.

Está escrito en C# sobre .NET 10 y WPF con MVVM.

C# .NET 10 WPF MVVM JSON

CARACTERÍSTICAS PRINCIPALES

DATOS PRINCIPALES PRIMERO

El técnico debe rellenar los datos principales antes de poder rellenar el resto de campos.

ALTA RÁPIDA DE UN SERVICIO

Sólo cuatro datos obligatorios para poder empezar a planificar.

CUATRO VISTAS

El mismo trabajo, mirado de cuatro maneras:

  • Tablero para ver lo que falta por rellenar.
  • Calendario para planificar.
  • Carga para repartir el trabajo con criterio.
  • BBDD para encontrar cualquier servicio.

FILTROS DE BÚSQUEDA

Filtros rápidos por estado, técnico, norma y periodo.
Los filtros aplicados son comunes a las 4 vistas.

GRUPOS

Un servicio con varias tomas de notas se puede llevar por separado o como un solo trabajo.
Basta con unirlas en un grupo: pasan a dibujarse como una sola barra y sus fechas se mueven juntas.

ESPACIO DE CALENDARIO OPTIMIZADO

Los paneles se colapsan y el calendario se reajusta automáticamente para ocupar el sitio que queda libre.

AVANCE EN PORCENTAJE

Cada toma de notas dice cuánto lleva hecho, en porcentaje ponderado por el peso de cada apartado.

FECHA DE LOS SERVICIOS

Las fechas se cambian arrastrando la barra: por el centro se mueve entera, por los extremos se estira solo el inicio o solo el fin.
Las fechas se pueden bloquear y la barra muestra el símbolo de un candado.

FECHA DE LLEGADA DE MUESTRAS

Se puede marcar la fecha de llegada de las muestras y la barra muestra el símbolo de una caja.

APARTADOS CONFIGURABLES

Listado de técnicos. Se puede añadir, modificar y eliminar sin riesgo a eliminar tomas de notas existentes.
Estados de los servicios. Se pueden añadir hasta 4 estados más, con selección de colores y si cuenta en carga de trabajo o no.
También se puede modificar la tarifa por hora, las horas diarias de trabajo y los días laborales de cada mes.

OTROS DETALLES

En las tomas de notas se pueden configurar campos autorellenables, restricciones de relleno (por ejemplo solo letras o solo números), restricciones de caracteres (por ejemplo solo válido 1 carácter), cálculos internos (por ejemplo si una muestra cabe o no dependiendo de su tamaño) y mucho más.

Un apartado que no aplique se marca N/A y deja de contar.

Un servicio se puede ensayar contra varias normas a la vez, cada una con su catálogo de equipos.

Las pestañas se arrastran para reordenarlas, como en un navegador.

El programa avisa cuando el laboratorio publica una versión nueva, sin bloquear el trabajo de nadie.

Las tomas de notas y la base de datos se exportan con un click.

Decisiones de diseño

Sin servidor

Todo vive en una carpeta compartida: las tomas de notas, la lista de técnicos, la tarifa y los estados. El programa la escanea al abrirse y no hay nada más que instalar ni mantener.

Las normas son datos

Las tomas de notas son un fichero JSON con sus apartados, campos y reglas. Añadir, modificar o retirar un archivo es sencillo y escalable.

Dos versiones conviviendo

Con varios equipos hay días con dos versiones del programa a la vez. Lo que una versión no entiende de un fichero se conserva en vez de descartarse, y una versión antigua puede leer un fichero nuevo pero no sobrescribirlo.
